# 一、PHP序列化与反序列化
## 1. 基础概念
+ 序列化：将变量/对象的数据转换为字符串，用于存储、网络传输。
+ 反序列化：将序列化后的字符串，还原为原本的变量/对象。
+ 核心函数：
    - `serialize()`：将对象/变量转为序列化字符串
    - `unserialize()`：将序列化字符串还原为对象/变量

### 补充概念
1. **类**：一类事物的抽象定义，包含**属性**（特征）、**方法**（动作/功能）。  
示例：
    - 汽车类：属性（颜色、马力），方法（启动、刹车）
    - 人类：属性（姓名、身高），方法（吃饭、睡觉）
2. **对象**：类在内存中的实例化产物，是具体的个体。  
示例：车牌号京Axxxx的汽车、身份证号11010xxxxx的张三。
3. 主流编程语言（除C语言外）基本都支持面向对象与序列化操作。
4. 流转示意：对象 → 序列化 → 字节码/字符串 → 网络传输/存储 → 反序列化 → 还原对象

## 2. 无类序列化案例
### 案例1 基础字符串序列化
```php
<?php
error_reporting(0);
include "flag.php";
$KEY = "KFC";
$str = $_GET['str'];
if(unserialize($str)===$KEY)
{
echo "$flag" ."</br>";
}
show_source(__FILE__);
?>
```

**解题操作**  
使用PHP在线工具执行序列化代码：

```php
<?php
echo serialize('KFC');
?>
```

输出结果：`s:3:"KFC";`

格式说明：`s`代表字符串，`6`代表字符串字符长度。

构造 payload：`?str=s:3:"KFC";`

### 案例2 CTF Cookie序列化题目
页面代码：

```php
...
<?php
error_reporting(0);
include_once("flag.php");
$cookie = $_COOKIE['ISecer'];
if(isset($_GET['hint'])){
show_source(__FILE__);
}
elseif (unserialize($cookie) === "$KEY")
{
echo "$flag";
}
else
{
?>
<html>
<head>
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
<title>Login</title>
<link rel="stylesheet" href="admin.css" type="text/css">
</head>
<body><br>
<div class="container" align="center">
<form method="POST" action="#">
<p><input name="user" type="text" placeholder="Username"></p>
<p><input name="password" type="password">
</p>
<p><input value="Login" type="button" /></p>
</form>
</div>
</body>
<?php
}
$KEY = 'ISecer:www.isecer.com';
?>
```

**错误思路**  
直接序列化`ISecer:www.isecer.com`，得到`s:21:"ISecer:www.isecer.com";`，设置Cookie访问，结果无效。  
原因：`$KEY`变量在判断逻辑**之后**赋值，判断执行时`$KEY`为空字符串。

**正确解法**  
序列化空字符串：

```php
<?php
echo serialize("");
?>
```

输出：`s:0:"";`  
构造请求包，设置`Cookie: ISecer=s:0:"";`

```php
<?php
class Person{

}
$p = new Person();
$obj = serialize($p);
print_r($obj);
```

格式说明：`O`代表对象，`6`为类名字符长度，`2`为对象属性个数。

### （2）对象反序列化

### （3）修改属性后反序列化
简单来说，“修改属性后反序列化”指的是：在将一个对象反序列化（还原成程序中的对象）之前，**人为地修改了代表该对象的“序列化字符串”的内容**。

```php
<?php
class Person{
public $name = 'Jack';
public $age = 18;
}
$clz = 'O:6:"Person":2:{s:4:"name";s:3:"Bob";s:3:"age";i:25;}';
$per = unserialize($clz);
print_r($clz);
echo "<br>";
echo $per->name;
?>
```

## 4. 不同访问修饰符的序列化格式
1. `public`（公共）：本类、子类、外部均可访问，序列化直接显示属性名。
2. `protected`（受保护）：仅本类、子类可访问，序列化格式：`\x00*\x00属性名`（`\x00`为空字节）。
3. `private`（私有）：仅本类内部可访问，序列化格式：`\x00类名\x00属性名`。

示例：

```php
<?php
class Person{
public $name = 'Jack';
protected $hobby = 'eat';
private $age = 18;
}
$p = new Person();
$obj = serialize($p);
echo "<br>";
print_r($obj);
?>
```

![](/img/posts/序列化漏洞/04.png)

输出结果：`O:6:"Person":3:{s:4:"name";s:4:"Jack";s:8:"*hobby";s:3:"eat";s:11:"Personage";i:18;}`

## **5. __wakeup 绕过**
+ **原理：** 某些 PHP 版本中，如果序列化字符串表示的对象属性个数，大于实际定义的属性个数，PHP 会跳过 `__wakeup()` 方法。
+ **动作：** 将 `O:6:"Person":1:{...}` 中的 `1` 改为 `2` 或更大。
+ **用途：** 绕过 `__wakeup` 中可能存在的安全检测。

# 二、PHP魔术方法
魔术方法：PHP在特定场景下**自动调用**的内置方法，序列化漏洞核心利用点。

> 注：测试 PHP，为直观显示输出结果，我将 `<br>` HTML换行标签换成了 `\n` 纯文本换行符，方便直观分行。但部署到 Apache、Nginx 等 Web 服务器、浏览器访问时需改用 `<br>`，因为浏览器会把 PHP 输出内容当作 HTML 解析，文本换行 `\n` 只会显示成空格，只有 `<br>` 才能实现页面换行效果。
>

## 1. __construct 与 __destruct
+ `__construct()`：构造方法，**对象创建时自动调用**。
+ `__destruct()`：析构方法，**对象销毁时自动调用**。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person{
public $name='Jack';
function __construct()
{
echo "<br>调用"."__construct";
echo "<br>";
}
function __destruct()
{
echo "调用"."__destruct";
echo "<br>";
}
}
$a= new Person();
echo serialize($a);
echo "<br>";
?>
```

![](/img/posts/序列化漏洞/05.png)

流程推演：

1. new 一个对象会触发 `__construct` 并 echo '调用 construct'
2. 执行序列化任务
3. **整个 PHP 脚本运行结束**（或变量被手动 unset）时，系统开始清理内存并销毁对象，此时会触发 `__destruct`，并 echo '调用 destruct'。

## 2. __sleep 与 __wakeup
+ `__sleep()`：**对象序列化时自动调用**。
+ `__wakeup()`：**对象反序列化时自动调用**。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person{
public $name='Jack';
function __construct()
{
echo "调用"."__construct";
echo "<br>";
}
function __destruct()
{
echo "调用"."__destruct";
echo "<br>";
}
function __sleep()
{
echo "调用"."__sleep";
echo "<br>";
return array("name");
}
function __wakeup()
{
echo "调用"."__wakeup";
echo "<br>";
}
}
$a= new Person();
echo serialize($a);
$b='O:6:"Person":1:{s:4:"name";s:4:"Jack";}';
echo "<br>";

$c=unserialize($b);
var_dump($c);
?>
```

![](/img/posts/序列化漏洞/06.png)

流程推演：

1. `new` 一个对象 `$a`，触发 `__construct`。 
2. 调用 `serialize($a)`，在转换为字符串之前，触发 `__sleep`。
3. echo 打印序列化结果。
4. 调用 `unserialize()`，系统根据字符串在内存中**生成了一个全新的对象**，并触发 `__wakeup`。
5. var_dump 打印反序列化结果。
6. 当程序彻底结束运行时，系统开始清空内存。因为此时内存中**同时存活住了两个对象**（一开始 `new` 出来的 `$a`，和后来 `unserialize` 捏造出来的新对象），连续触发了两次 `__destruct`。

注意：

反序列化的入口必须是字符串，绝对不能是对象本身。`unserialize()` 这个函数的功能是”把字符串变回对象”。因此，它只能接收字符串作为参数。也不可以直接用 echo 打印对象。

因此代码不可以写成：

```php
$a= new Person();
echo serialize($a);
$b = $a; 			//给 $b 赋值一串字符串：$b='O:6:"Person":1:{s:4:"name";s:4:"Jack";}';
$c = unserialize($b);
echo "$c";		//var_dump($c); 或者用 print_r($c);
```

## 3. __get 与 __set
+ `__get()`：访问**不存在/私有属性**时自动调用。
+ `__set()`：赋值给**不存在/私有属性**时自动调用。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person {
public $name = 'Jack';
private $str = 'hello';
function __construct() {
echo "<br>";
echo "调用 " ." __construct()";
}
function __destruct() {
echo "<br>";
echo "调用 " . "__destruct()";
echo "<br>";
}
function __get($b) {
echo "<br>";
echo "调用 " . "__get";
echo "<br>";
return $this->str;
}
function __set($name,$value) {
echo "<br>";
echo "调用 " . "__set";
echo "<br>";
$this->str = $value;
}
}
$a= new Person();
echo $a->age;
$a->age=13;
echo $a->str;
?>
```

![](/img/posts/序列化漏洞/07.png)

流程推演：

1. `new` 一个对象 `$a`，触发 `__construct` 执行。输出 `调用 __construct()`。
2. 读拦截 (`__get`)：执行 `echo $a->age;`。因为 `age` 这个属性在类里**不可访问**，系统立刻拦截，触发了 `__get` 方法。
    1. `__get` 内部先输出了 `调用 __get`。
    2. 然后它执行了 `return $this->str;`初始值应该是 `'hello'`。
3. `echo` 拿到返回值，打印出了 `hello`。
4. 写拦截 (`__set`)： 执行 `$a->age = 13;`给一个不存在的属性 `age` 强行赋值。系统再次拦截，触发了 `__set` 方法。
    1. `__set` 内部先输出了 `调用 __set`。
    2. 接着执行 `$this->str = $value;`传进来的 `13`赋值给了内部的 `$str` 属性。
5. 再次读拦截： 执行 `echo $a->str;`
    - 系统再次触发 `__get`，输出 `调用 __get`。
    - 此时返回 `$this->str`，因为上一步它已经被改成了 `13`，所以外部的 `echo` 最终打印出了 `13`。
6. 脚本执行结束，内存清空销毁对象，自动触发 `__destruct`，输出 `调用 __destruct()`。

## 4. __call 与 __callStatic
+ `__call()`：调用**对象中不存在的实例方法**时自动调用。
+ `__callStatic()`：调用**类中不存在的静态方法**时自动调用。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person {
public $name = 'Jack';
public $str = 'hello';
public static function myStaticMethod() {
echo "<br>";
echo "调用 " . "myStaticMethod";
echo "<br>";
}
function __construct() {
echo "<br>";
echo "调用 " ." __construct()";
echo "<br>";
}
function __destruct() {
echo "<br>";
echo "调用 " . "__destruct()";
echo "<br>";
}
function __call($b,$q) {
echo "<br>";
echo "调用 " . "__call";
echo "<br>";
return $this->str;
}
public static function __callStatic($func, $arguments){
echo "<br>";
echo "调用 " . "__callStatic";
echo "<br>";
}
}
$a= new Person();
echo $a->method();
Person::myStaticMethod();
Person::method2();
?>
```

![](/img/posts/序列化漏洞/08.png)

流程推演：

1. 创建对象 `$a`。自动触发 `__construct()`。输出`调用 __construct()`
2. `echo $a->method();`PHP 引擎试图在 `$a` 这个对象里寻找一个叫 `method()` 的普通方法。但是并不存在。触发 `__call($b, $q)`，先输出 `调用 __call`。接着代码里写了 `return $this->str;`，于是把内部属性 `'hello'` 返回给了外面的 `echo`，最终在屏幕上打印出了 `hello`。
3. `Person::myStaticMethod();`，`::` 是静态调用的符号。PHP 引擎去 `Person` 类里找 `myStaticMethod()`。发现这个静态方法真实存在，且权限是 `public`。直接执行该方法，输出 `调用 myStaticMethod`。
4. `Person::method2();`PHP 引擎试图静态调用一个叫 `method2()` 的方法。发现并不存在。触发`__callStatic($func, $arguments)`，输出 `调用 __callStatic`。
5. 脚本运行结束，内存开始清空自动触发 `__destruct()`。输出`调用 __destruct()`。

## 5. __toString 与 __clone
+ `__toString()`：**对象被当作字符串使用/输出时**自动调用。
+ `__clone()`：使用`clone`关键字克隆对象时自动调用。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person {
public $name = 'Jack';
function __construct() {
echo "<br>";
echo "调用 " ." __construct()";
echo "<br>";
}
function __destruct() {
echo "<br>";
echo "调用 " . "__destruct()";
echo "<br>";
}
function __toString() {
echo "<br>";
echo "调用 " . "__toString";
echo "<br>";
return $this->name;
}
function __clone() {
echo "<br>";
echo "调用 " . "__clone";
echo "<br>";
}
}
$a= new Person();
echo $a . '<br>';
$b = $a;
echo $a === $b;
$c = clone $a;
echo $a === $c;
?>
```

![](/img/posts/序列化漏洞/09.png)

流程推演：

1. new 一个对象`$a`，输出`调用 __construct()`
2. `echo $a . '<br>';`对象 `$a` 和一个字符串 `'<br>'` 拼接在一起打印。为了防止报错，系统强行触发了对象的 `__toString()` 方法。输出`调用 __toString`，然后把返回的 `$this->name`（也就是 `'Jack'`）拼接到 `<br>` 前面输出。
3. **引用赋值**`$b = $a;`
4. `echo $a === $b;`结果为 `true`。经过 `echo` 的强制类型转换。打印出数字 `1`。
5. `$c = clone $a;`**创造了一个新对象** `$c`，它的属性和 `$a` 一模一样，但它们在内存中是独立的两个实体。新对象诞生时自动触发 `__clone()`。输出`调用 __clone`。
6. `echo $a === $c;`再次比较，虽然长得一样，但已经是两个不同的实体了，所以结果为 `false`。`echo false` 在 PHP 中输出空字符串。
7. 代码执行结束，内存开始清空。两个对象被销毁，连续打印两次 `调用 __destruct()`。

## 6. __invoke
将**对象当作函数直接调用**时自动触发。  
示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person {
public $name = 'Jack';
function __construct() {
echo "<br>";
echo "调用 " ." __construct()";
echo "<br>";
}
function __destruct() {
echo "<br>";
echo "调用 " . "__destruct()";
echo "<br>";
}
function __invoke($p1,$p2) {
echo "<br>";
echo "调用 " . "__invoke";
echo "<br>";
return $p1 . "---" . $p2;
}
}
$a= new Person();
echo $a("Jack","is a hacker");
?>
```

![](/img/posts/序列化漏洞/10.png)

流程推演：

1. 创建对象 `$a`，触发 `__construct()`。`调用 __construct()`。
2. `echo $a("Jack","is a hacker");`把一个对象（`$a`）当成了函数来加括号调用。括号里传的两个字符串 `"Jack"` 和 `"is a hacker"`传给了 `__invoke($p1, $p2)`。
3. 先触发内部的 `echo` 输出 `调用 __invoke`。接着执行 `return` 语句将两个参数拼接。输出`Jack---is a hacker`。
4. 程序结束，内存清空，对象销毁，触发 `__destruct()`。输出`调用 __destruct()`。

## 7. __isset 与 __unset
+ `__isset()`：对**不可访问属性**执行`isset()/empty()`时自动调用。
+ `__unset()`：对**不可访问属性**执行`unset()`销毁时自动调用。

示例：

```php
<?php
header("Content-type: text/html; charset=utf-8");
highlight_file(__FILE__);
class Person
{
public $sex;
private $name;
private $age;
public function __construct($name = '', $age = 25, $sex = '男')
{
$this->name = $name;
$this->age = $age;
$this->sex = $sex;
}
public function __isset($name)
{
echo "<br>";
echo "调用 " ." __isset()";
echo "<br>";
}
public function __unset($name)
{
echo "<br>";
echo "调用 " ." __unset()";
echo "<br>";
}
}
$person = new Person('Jack', 18, 'male');
// __isset()
echo isset($person->sex);
echo isset($person->name);
echo isset($person->age);
// __unset()
echo "\n";
unset($person->name);
unset($person->sex);
echo isset($person->sex) ? 'has' : 'not_has', "\n";
?>
```

![](/img/posts/序列化漏洞/11.png)

流程推演：

1. `new` 一个对象，包含公开属性 `sex`，私有属性 `name` 和 `age`。 
2. `echo isset($person->sex);`代码可以直接拿到公开的数据 `sex`（不触发魔术方法）；但是对于私有数据无法直接接触。因为 `sex` 是 `public`，系统直接放行，结果为 `true`。经过 `echo` 的强制类型转换，屏幕上打出了数字 `1`。
3. `echo isset($person->name);``echo isset($person->age);`当执行 `isset` 探测 `name`**和**`age` 时，因为权限不够，**连续两次**被拦截并触发了 `__isset` 方法，输出了两次提示。 
4. 代码试图用 `unset` 销毁私有的 `name`，再次被拦截，触发了 `__unset` 方法并输出提示。
5. 当试图销毁公开的 `sex` 时，因为权限足够，系统没有拦截，而是直接在内存里把它真实删除了。 
6. 最后用三目运算符再次探测 `sex` 时，发现它已经被删没了，所以输出了 `not_has`。

# 三、CTF 序列化实战题目
## 示例：CTF-XSS 结合反序列化
页面代码 `ctf_xss.php`

```php
<?php
highlight_file(__file__);
$a = unserialize($_GET['k']);
echo $a;
?>
```

## 解题思路
1. 代码调用`unserialize`反序列化，且直接`echo`输出对象，触发`__toString`魔术方法。
2. 利用PHP**原生类**（无需自定义）`Exception`，该类存在`__toString`方法。
3. 构造包含XSS语句的Exception对象，序列化后传入参数。

## 构造代码
```php
<?php
$e = new Exception("<script>alert(1)</script>");
echo urlencode(serialize($e));
?>
```

将输出字符串作为`k`参数传入，触发XSS弹窗。

流程推演：

1. 当服务器执行到 `echo $a;` 时，强行触发了 `Exception` 对象的 `__toString`。
2. `__toString` 强制输出了报错信息，导致原本在 PHP 后端内存对象里的恶意 JS 代码`<script>alert(1)</script>`被提取出来，当作一串普通的字符串，拼接到了最终要发送的 HTML 网页源码里。
3. 服务器把拼凑好的 HTML 源码通过网络发送给了普通用户的浏览器。前端开始逐行解析网页准备渲染画面。当浏览器解析到 `<script>` 这个标签时，它的 JS 引擎被瞬间激活执行了这句 JavaScript 语句，成功弹出了框框。

## 补充：查看PHP所有原生魔术方法类
```php
<?php
$classes = get_declared_classes();
foreach ($classes as $class) {
$methods = get_class_methods($class);
foreach ($methods as $method) {
```

### 利用：
+ **XSS / 信息泄露：** 利用 `Exception` 或 `Error`。遇到 `echo` 时，其 `__toString` 会将肚子里的报错信息（恶意代码）吐到前端。
+ **SSRF (内网探针) ：** 利用 `SoapClient`。触发其 `__call` 方法可强行向内网发送 HTTP 请求。
+ **文件/目录遍历：** 利用 `DirectoryIterator` 或 `FilesystemIterator` 配合 `__toString` 读取敏感目录。
+ **Phar 反序列化：** 利用 `Phar`。无需 `unserialize`，只需普通文件读取操作（如 `file_exists`, `filesize`, `file_get_contents`, `md5_file` 等）即可引爆反序列化。

# 四、PHP 反序列化攻击
+ **核心：** 寻找从入口unserialize()到危险函数的“多米诺骨牌”（POP 链）。
+ **显式入口 (函数类)：** 代码直接调用 `unserialize()`。
+ **隐式入口 (协议/机制类)：**
    - **Phar 协议：** 利用 `phar://` 伪协议，通过文件操作触发。
    - **Session 机制：** 利用 `session.serialize_handler` 引擎不一致触发。

## Exception XSS 
+ **触发条件：** 存在 `unserialize()` 入口 && `echo`/`print` 输出点。
+ **动作：** 构造 `new Exception("<script>...")`。
+ **关键点：** 触发 `Exception::__toString`。

## Session 反序列化
+ **触发条件：** 存在“存取引擎不一致” (`php` vs `php_serialize`)。
+ **动作：** 
    1. 寻找写入 Session 的接口，投毒 Payload：| + 序列化字符串。
    2. 触发读取 Session 的页面，触发引擎自动反序列化。
+ **关键点：** `session.auto_start=1` 导致的顺序冲突。
+ 注：若条件竞争不成功，**增加上传文件大小**（上传超大文件）以延长 Session 文件存活时间，扩大 0.01 秒的窗口期。 增加文件大小 = **“让子弹多飞一会儿”**，增加命中概率。

## Phar 反序列化
+ **触发条件：** 代码存在任意文件操作函数 (`file_exists`, `md5_file` 等)。
+ **动作：** `phar://` + 伪装后缀 (`.jpg`)。
+ **关键点：** 利用 PHP 底层 `phar://` 协议强制反序列化。
+ 注：Phar 文件必须包含合法签名（如 `\x00\x00\xfe\x01`）。若手动修改或生成时破坏了签名，PHP 将拒绝识别文件，导致漏洞无法触发。

# 五、总结
## Q1: PHP 序列化漏洞中，有哪些魔术方法？
+ `__construct` ⭐️  
构造方法，仅`new`创建对象时自动触发，反序列化不会执行。
+ `__destruct` ⭐️  
析构方法，对象销毁、脚本运行结束、反序列化完成后自动触发。
+ `__toString`  
将对象当作字符串输出、拼接时自动触发。
+ `__wakeup` ⭐️  
执行反序列化`unserialize()`时最先触发，存在经典属性数量绕过漏洞。
+ `__sleep`  
执行序列化`serialize()`对象前自动触发。
+ `__call`  
调用不存在或无访问权限的方法时自动触发。
+ `__get`  
读取不存在、私有/受保护不可访问的属性时自动触发。
+ `__set`  
修改不存在、私有/受保护不可访问的属性时自动触发。
+ `__invoke`  
把对象当作函数（`$obj()`）调用时自动触发。

## Q2: 序列化和反序列化的过程是什么？
序列化：把内存中的对象，转换成字符串或字节码，便于存储和网络传输

反序列化：把字符串或字节码还原为内存中的对象

## Q3: 序列化漏洞的产生原因是什么？
用户可以通过 HTTP、或其他网络协议向服务器发送任意的序列化字符串或字节码，服务器未经严格验证就进行了反序列化。

## Q4: 反序列化漏洞的危害有哪些？
RCE（远程代码执行），权限提升，敏感信息泄露，DDOS攻击，内网渗透（以该服务器为跳板，攻击公司内网中的其他设备）

## Q5: POP链是什么？
攻击者通过控制对象的属性，将程序中现有的多个代码片段（Gadgets）像接龙一样串联起来，最终形成的一条攻击路径。

## Q6: session 反序列化是什么？
session 反序列化漏洞是指攻击者通过篡改储存在 session 中的序列化数据，利用服务器解析（还原）这些数据时的逻辑缺陷，从而实现越权访问或远程执行恶意代码的安全漏洞。

## Q7: session 反序列化的形成原因是什么？
1. php 使用了不同的 session 序列化引擎处理 session（存入 Session 时使用新引擎 `php_serialize`（无竖线），读取时使用旧引擎 `php`（以竖线 `|` 分割键值）。核心在于读取时，PHP 引擎会对 Session 中的竖线 `|` 进行切分，并将右侧数据强制反序列化。）
2. php 保存 session 的过程是序列化，php 读取 session 的过程是反序列化。

## Q8: session 反序列化的危害是什么？
RCE（远程代码执行）

## Q9: session 序列化引擎有哪些？
PHP、PHP_serialize、PHP_binary

## Q10: 文件上传进度反序列化是什么？
文件上传进度反序列化是指攻击者通过在上传表单中构造恶意的进度标识符，利用 PHP 自动将上传信息存入 session 的机制，结合 session 引擎解析差异，强制服务器在后台还原恶意对象从而触发代码执行。

## Q11: 文件上传进度反序列化的作用是什么？
php会话上传进度，phpinfo信息泄露可以看到对应的信息

+ `session.upload_progress.enabled` 会话上传进度是否开启
+ `session.upload_progress.name` 会话上传进度名
+ `session.upload_progress.cleanup` 会话上传进度是否会自动清理

当一个文件上传时，PHP 会检查 HTTP 请求。如果发现请求中包含一个特定的变量（默认名称为`PHP_SESSION_UPLOAD_PROGRESS`），它就会在 `$_SESSION` 数组中创建一个特殊的键。**可用于Session序列化漏洞**

这个键里包含了文件的总大小、当前已上传的大小、预计剩余时间等实时数据。前端可以通过另一个异步请求（AJAX）读取这些 Session 数据，从而绘制出进度条。
