# 一、[陇剑杯 2021]jwt
## Q1：JWT 是什么？
**JWT（JSON Web Token）**：JSON格式的Web令牌，是一种**轻量级、无状态**的身份认证、授权标准（RFC7519）。
用于前后端分离、分布式系统登录鉴权，替代传统 Session。

### 1. 核心特点
1. **无状态**：服务端不用存储会话数据，全部信息存在Token里，天然适配集群、微服务
2. **轻量化**：Base64编码字符串，体积小，可放URL、Header、Cookie
3. **自包含**：Token自带用户身份、权限、过期时间等业务信息
4. **防篡改**：通过签名校验，数据无法被随意修改

### 2. JWT 三段结构（用 `.` 分割）
格式：`Header.Payload.Signature`

#### 2.1 Header 头部 ---- Base64URL编码
作用：声明**加密算法**、令牌类型
示例JSON：

```json
{
  "alg": "HS256", // 签名算法：HS256对称加密，RS256非对称
  "typ": "JWT"    // 类型固定JWT
}
```

#### 2.2 Payload 载荷----Base64URL编码
存放业务数据，分**标准声明**和**自定义声明**

> 重要：Payload只是编码，**未加密**，不能存密码、密钥等敏感数据！
>

#### 标准内置字段
| 字段 | 含义 |
| --- | --- |
| iss | 签发者（服务端域名） |
| sub | 用户唯一标识（用户ID） |
| aud | 接收方（客户端） |
| exp | 过期时间戳（必填，超时失效） |
| nbf | 生效时间（在此之前不可用） |
| iat | 签发时间 |
| jti | 令牌唯一ID（用于注销、黑名单） |

#### 自定义字段
存放权限、角色、用户名等，例：`{"role":"admin","uid":1001}`

#### 2.3 Signature 签名
防止Header+Payload被篡改，生成逻辑：

1. 将 Header、Payload 分别做 Base64URL 编码
2. 拼接成 `base64(header).base64(payload)`
3. 使用 Header 指定算法 + 密钥/私钥 加密，得到签名
+ 对称加密 HS256：服务端统一一个密钥，签发、校验都用同一密钥
+ 非对称加密 RS256：私钥签发Token，公钥校验，适合多服务场景

## Q2：PAM 认证后门是什么？
### 1. 定义
**PAM（Pluggable Authentication Modules，可插拔认证模块）** 是Linux系统统一的底层认证框架。
系统登录、`sudo`提权、修改用户密码、SSH登录等所有身份校验操作，底层都会调用PAM模块。

+ 主配置目录：`/etc/pam.d/`
+ 全局公共认证配置：`/etc/pam.d/common-auth`，所有系统服务共用这套认证规则。
+ 工作机制：通过加载`.so`动态链接库文件，执行认证校验逻辑。

### 2. PAM认证后门核心原理
攻击者利用PAM加载自定义动态库的特性制作持久后门：

1. 编写恶意C代码，编译生成恶意动态链接库（示例：`looter.so`）；
2. 修改全局认证配置 `/etc/pam.d/common-auth`，添加加载恶意`.so`模块的配置；
3. 恶意模块实现两大攻击能力：
    1. **万能密码绕过**：输入攻击者预设的特殊密码，直接放行认证，无视用户真实密码；
    2. **窃取明文密码**：合法用户正常登录、sudo时，悄悄捕获并落地用户输入的明文账号密码。

### 3. 后门特点
PAM属于系统底层认证机制，隐蔽性极强：

+ 普通改密码、重启服务无法清除后门；
+ 就算原始入侵漏洞被修复、管理员重置所有用户密码，攻击者依旧能靠万能密码重新登录；
+ 常规进程、日志排查很难定位PAM恶意模块。

## Q3：frp 是什么？
**frp = Fast Reverse Proxy**

快速反向代理，一款**开源内网穿透工具**

**1. 组成**

+ frps → frp server 服务端
部署在有公网IP的云服务器上
+ frpc → frp client 客户端
部署在内网设备（家里电脑、校园网主机）

**2. 核心用途（内网穿透）**

实现外网访问局域网内设备，常见场景：

1. 外网远程SSH连接家里Linux主机
2. 在外远程桌面控制Windows电脑
3. 将本地Web项目暴露公网，给他人测试
4. 外网访问NAS网盘、智能家居服务

**3. 简单工作流程**

1. 内网机器启动 **frpc**，主动出站连接云服务器 **frps**，维持长连接隧道
2. 外网用户访问「云服务器IP:远端端口」
3. frps收到请求，通过隧道转发给frpc
4. frpc把流量交给内网本地程序
5. 返回数据原路送回外网访问者

**4. 支持协议**

TCP、UDP、HTTP、HTTPS、STCP（安全隧道，访客验证）、XTCP（点对点P2P穿透）

**5. 基础文件说明**

+ frps.ini：服务端配置
+ frpc.ini：客户端配置

配置示例：

_(注：frp 在较新的版本中官方推荐使用 _`.toml`_ 格式)_

1. `frps.ini`：服务端配置 (部署在公网服务器)

这份配置告诉公网服务器，应该在哪些端口监听客户端的连接，以及开放哪些端口给外部用户访问。

```properties
[common]
# 核心通信端口：frp 服务端监听的端口，等待你本地的 frpc 来连接
bind_port = 7000

# 身份验证：设置一个 token 防止别人随意连接你的服务端
token = my_secure_password_123

# Web 穿透专用：如果需要穿透 HTTP 服务，必须配置这个公网访问端口
vhost_http_port = 8080
```

---

2. `frpc.ini`：客户端配置

这份配置告诉本地程序，去哪里寻找服务端，以及要把本地的哪些服务（如 Web 测试环境、SSH 终端）映射到公网出去。

```properties
[common]
# 指向服务端的公网 IP 地址
server_addr = 1.2.3.4
# 必须与服务端 bind_port 保持一致
server_port = 7000
# 必须与服务端 token 保持一致
token = my_secure_password_123

# --- 示例 1：穿透本地的 Web 测试环境 ---
# （比如你本地用 phpStudy 或 Ubuntu 的 Vulhub 搭建了一个漏洞靶场，运行在 80 端口）
[web_test_env]
type = http
local_ip = 127.0.0.1
local_port = 80
# 外部访问的域名。配置好后，访问 http://test.yourdomain.com:8080 就能看到本地 80 端口的内容
custom_domains = test.yourdomain.com

# --- 示例 2：穿透 SSH 端口进行远程管理 ---
[ssh_access]
type = tcp
local_ip = 127.0.0.1
local_port = 22
# 将公网服务器的 6000 端口，映射到本地的 22 端口
# 配置好后，在外部通过 ssh -p 6000 user@1.2.3.4 即可连接到这台本地机器
remote_port = 6000

```

当启动这两个服务后：

1. 本地的 `frpc` 会带着 `token`，去敲公网 IP `1.2.3.4` 的 `7000` 端口的门。
2. `frps` 验证通过后，两者建立起一条隐秘的隧道。
3. 当外部网络有人访问 `1.2.3.4:6000` 时，`frps` 就会把流量顺着隧道丢给 `frpc`，`frpc` 再把流量转发给本机的 `22` 端口。

## Q4：SOCKS5 是什么？
**1. 定义**

**SOCKS5** 是一种**代理协议**（Socket Secure Version 5），工作在**会话层**。

SOCKS5 ≠ HTTP代理

HTTP代理：**只支持网页HTTP/HTTPS流量**

SOCKS5：**几乎所有流量都能转发**（TCP绝大多数程序）

**2.  特点**

+ 支持 TCP、UDP
+ 不解读应用层数据（只管转发数据包）
+ 支持账号密码认证
+ 可以搭配 FRP、V2Ray、Clash 等工具使用
+ 本身不加密。原始SOCKS5流量是明文传输；想要加密，一般外面套一层隧道（FRP/TLS、ShadowSocks等）。

**3. 和 FRP 的结合**

frp 可以直接**在客户端配置开启SOCKS5隧道**
作用：在内网电脑运行frpc，外网通过frps连接这条socks5代理，**使用内网机器的网络上网**。

frpc.ini 里 SOCKS5 配置实例

```properties
[common]
server_addr = x.x.x.x
server_port = 7000
token = 自定义密钥

[socks-proxy]
type = tcp
local_ip = 127.0.0.1
local_port = 1080
remote_port = 1080
```

+ 内网本机开启 socks5：`127.0.0.1:1080`
+ 外网设备连接 `服务器IP:1080`
流量 → frps → frpc → 内网socks代理 → 使用内网网络

> 另一种：frp**内置socks5服务**（不用本地额外开socks程序）
>

```properties
[proxy-socks5]
type = socks5
remote_port = 1080
```

 **4. SOCKS5 常见使用场景**

1. 浏览器/Clash设置代理，走SOCKS5
2. SSH动态端口转发本质就是SOCKS5代理
3. FRP内网穿透，对外提供内网代理
4. 游戏、FTP、远程工具都能使用SOCKS5
