1. 数据库核心概念

1.1 什么是数据库

数据库是长期存储在计算机内、有组织、可共享的数据集合，解决海量数据管理问题（对比Excel：支持上亿条数据、多人同时操作且保证数据不混乱）。‌‌‌‌‌‌‌‌‌​​‌​‌​‌‍‌‌‌‌‌‌‌‌‌​​‌‌‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​​‍‌‌‌‌‌‌‌‌‌​​‌​​‌​‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​‌​​​‌‍‌‌‌‌‌‌‌‌‌​​‌‌​‌​‍‌‌‌‌‌‌‌‌‌‌​‌​​‌​‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​‌‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​​‍‌‌‌‌‌‌‌‌‌‌​‌​​​‌‍‌‌‌‌‌‌‌‌‌​​​‌​‌‌‍‌‌‌‌‌‌‌‌‌​​‌​​​​‍‌‌‌‌‌‌‌‌‌​​​‌‌‌‌‍

数据库层级结构（类比学校）

层级 类比 示例
顶层：数据库 整个学校 school 库（存储校园所有数据）
中层：数据表 学校不同部门 users 表、classes 表
底层：字段+数据 表头+行内容 字段：id、name，数据：2025001、张三

1.2 数据库管理系统（DBMS）

数据库的”管家”，负责管理数据访问、存储规则，常见类型：

  1. Oracle：功能强、收费，银行/电信常用
  2. SQL Server：适配Windows，政府单位常用
  3. MySQL：开源免费、轻巧，校园系统/网站主流

2. 数据库连接操作

2.1 Navicat 可视化连接

  1. 打开 Navicat → 左上角「连接」→ 选择「MySQL」
  2. 填写核心信息：
    • 主机：localhost（本地数据库）
    • 端口：3306（MySQL 默认端口）
    • 用户名：root（超级管理员）
    • 密码：安装 MySQL 时设置的密码
  3. 点击「测试连接」，提示”连接成功”即完成
  4. 双击连接名，即可查看/操作数据库

2.2 命令行连接

  • -u：指定用户名
  • -p：需要输入密码（输入时不显示，属正常现象）
  • 回车后输入密码，再次回车即可登录

9.1.4 连接规则

  1. 必须使用 on 写关联条件，区分 where 过滤条件；
  2. 多表关联时建议给表起别名简化书写；
  3. 区分内外连接：内连接只留交集，外连接保留单侧全量数据。

9.2 UNION 联合查询

多条查询结果纵向合并

9.2.1 基础语法

注意：

  1. 列数量必须完全一致：前后两条select查询返回的字段个数相同；
  2. 对应位置字段数据类型兼容：第1列都是字符串、第2列都是数字，不能一列字符串一列数字；
  3. 最终字段名以第一条select的列名为准；
  4. 排序写法：order by 写在整条语句末尾，作用于合并后的全部结果

9.2.2 UNION vs UNION ALL

关键字 去重 性能 使用场景
UNION 自动剔除完全重复数据 低（底层排序比对去重） 需要合并后剔除重复数据
UNION ALL 保留所有数据，不做去重 高（直接拼接结果） 确认无重复，追求查询速度

9.3 连接查询 vs UNION

  1. JOIN（左右内连接）：横向拼接
    多张表按关联条件左右合并字段，一行数据同时包含多表列；
    例：用户表+签到表，一行同时有用户名、签到次数。
  2. UNION：纵向拼接
    多条查询结果上下合并行，字段结构完全一致，只是叠加数据；
    例：把1班学生表、2班学生表合成一张完整学生列表。

10. SQL 注入漏洞

10.1 万能密码

漏洞根源

  • 直接将用户输入拼接到 SQL 语句的单引号中执行
  • 未检查/过滤特殊字符（如 '、OR、# 等），也未做转义处理
  • 攻击者可输入恶意字符篡改 SQL 逻辑

攻击原理

攻击者输入 123' or '1'='1，实现 3 个关键操作：

  1. 闭合原有 SQL 语句的单引号，打破查询限制
  2. 添加 '1'='1' 恒成立条件，让查询条件永远为真
  3. 注释多余内容，避免 SQL 语法错误

10.2 CTF 注入常用语句

核心系统库：information_schema

MySQL 自带系统字典库，储存所有数据库名、表名、字段名，注入查表必备。

系统表 存储内容
schemata 所有数据库信息
tables 所有数据表信息
columns 所有字段（列）信息
关键字段 含义
schema_name 数据库名
table_schema 表所属的数据库
table_name 数据表名
column_name 字段（列）名
