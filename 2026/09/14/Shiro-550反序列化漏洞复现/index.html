Shiro-550反序列化漏洞复现

发表于2026-09-14|更新于2026-09-14|靶机练习vulhub
|总字数:4k|阅读时长:15分钟

一、漏洞背景

1.1 什么是 Apache Shiro？

Apache Shiro 是Java 开源安全框架，专门做Web应用的身份安全模块，很多Java Web项目（网站、后台管理系统）会集成它。
它主要负责4件核心工作：‌‌‌‌‌‌‌‌‌​​‌​‌​‌‍‌‌‌‌‌‌‌‌‌​​‌‌‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​​‍‌‌‌‌‌‌‌‌‌​​‌​​‌​‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​‌​​​‌‍‌‌‌‌‌‌‌‌‌​​‌‌​‌​‍‌‌‌‌‌‌‌‌‌‌​‌​​‌​‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​‌‍‌‌‌‌‌‌‌‌‌​​‌​‌‌​‍‌‌‌‌‌‌‌‌‌​​​‌‌​​‍‌‌‌‌‌‌‌‌‌‌​‌​​​‌‍‌‌‌‌‌‌‌‌‌​​​‌​‌‌‍‌‌‌‌‌‌‌‌‌​​‌​​​​‍‌‌‌‌‌‌‌‌‌​​​‌‌‌‌‍

  • 身份认证：登录校验账号密码
  • 授权：判断你有没有权限访问页面/接口
  • 会话管理：维持用户登录状态
  • RememberMe（记住我）：勾选“记住我”，关闭浏览器下次不用重新登录

这个漏洞，就出在 RememberMe 记住我这个功能上。

1.2 RememberMe 正常的工作逻辑

正常场景：我们登录网站勾选【记住我】

  1. 服务器把我们的用户身份对象（Java对象，包含用户名等信息）序列化，转成一串二进制字节；
  2. 用内置AES密钥对这串二进制做加密；
  3. 加密后的字符串放到Cookie，字段名叫rememberMe，返回给浏览器保存；
  4. 下次我们再来访问网站，浏览器自动带上这个rememberMeCookie；
  5. 服务器读取Cookie，用同一个AES密钥解密，再反序列化变回Java对象，识别我是谁，直接免登录。

1.3 CVE-2016-4437 漏洞成因

Shiro 1.2.4及以下版本，源码里直接硬编码写死了AES加密密钥：
kPH+bIxk5D2deZiIxcaaaA==
这个密钥是公开的，所有人都能从源码里找到。

漏洞发生完整逻辑：

  1. 密钥固定公开 → 攻击者可以自己加密，伪造rememberMe内容；
  2. 攻击者使用ysoserial工具，构造恶意Java序列化对象（Gadget利用链）；
  3. 用这个公开固定AES密钥加密恶意对象，生成伪造的rememberMeCookie；
  4. 攻击者发送HTTP请求，带上伪造的rememberMe Cookie访问网站；
  5. 服务器收到Cookie：先用内置硬编码密钥解密 → 拿到二进制序列化数据；
  6. 服务器没有任何校验，直接对不可信的数据执行反序列化；
  7. 在反序列化解析对象的过程中，触发预先构造好的恶意代码，实现远程代码执行RCE。

即：
✅ 硬编码固定AES密钥（攻击者可控加密内容）
✅ 对来自Cookie的外部不可信输入，直接反序列化，没有校验

1.4 版本范围

受影响版本：Apache Shiro ≤ 1.2.4
在 1.2.5 版本修复：不再使用固定硬编码密钥，改成项目部署时，由用户自己配置独立密钥。

1.5 漏洞特点

  1. 不需要账号密码，不需要登录，直接发送带伪造rememberMe的请求就能打；
  2. 属于Java反序列化漏洞，依赖Java Gadget链（最常用CommonsCollections1）；
  3. 漏洞编号CVE-2016-4437，圈内俗称Shiro550（因为漏洞在issue编号550）。

1.6 补充：什么是序列化/反序列化？

  • 序列化：把内存里的Java对象，变成一串二进制字节，方便网络传输、存Cookie；
  • 反序列化：反过来，把二进制字节，恢复成内存里的Java对象；

风险点：反序列化的时候会自动执行对象里的部分代码。如果对象是恶意构造的，就执行攻击代码。

Q1：ysoserial 是什么？

1. 定义

ysoserial 是安全研究者 frohoff 开发的 Java反序列化Payload生成工具。自动生成构造好的恶意Java序列化二进制数据，用来打Java反序列化漏洞（Shiro550、Weblogic、JBoss等）

2. 核心概念

  1. Gadget Chain（利用链/小工具链）

Java 反序列化本身不会直接执行命令。
Gadget（小工具）就是项目 jar 包里本来就存在的一些类和方法；利用链 = 把这些现成 Gadget 按顺序串起来，当 Java 进行反序列化时，会自动依次调用这一串方法，最终执行系统命令。
ysoserial内置了大量写好的利用链：

  • URLDNS：仅触发DNS解析，无法执行系统命令，适合简易探测
  • CommonsCollections： 选 CC 系列利用链的第一步，就是先确认目标有没有这个 jar、是 3.x 还是 4.x。
利用链 限制条件
CC1 JDK 版本必须 ≤ jdk8u71，高版本 JDK 会失效
CC3 依赖 TemplatesImpl 类，对 JDK 版本敏感，兼容性差
CC5 要求 JDK ≥ jdk8u76，版本限制单向
CC6 入口为 HashSet，依靠 InvokerTransformer 完成反射调用；JDK6 ~ JDK21 大范围兼容，几乎无版本门槛
CC7 链路逻辑复杂，稳定性弱于 CC6
  1. 输出产物
    工具输出二进制序列化数据，不是明文。
    Shiro场景下：这个二进制还需要经过AES加密+Base64编码，才能放进rememberMe Cookie。

⚠️ysoserial不发包、不做加密，它只负责生成恶意二进制payload。

Q2：为什么要用DNSlog验证？

Shiro550属于无回显命令执行

  1. 执行命令的结果不会直接返回在网页响应里，看页面看不出是否执行成功；
  2. ping请求会触发DNS查询，这个请求会主动外带流量到dnslog平台；
  3. DNS请求不会受web页面回显限制，只要命令执行成功就一定会留下记录；
  4. 简单、轻量，不需要搭建额外服务器，比赛靶场最通用的验证手段。

方案一：DNSlog

2.1 获取DNSlog子域名

http://dnslog.cn/

访问 dnslog.cn，页面提供专属域名。

原理：只要靶机执行了ping xxx.dnslog.cn，靶机会发起DNS解析请求；dnslog平台会记录这条解析记录。
优势：无回显RCE首选。很多Shiro靶场命令执行没有页面回显，浏览器页面看不出任何变化，但DNS请求是一定会向外发的。

3.5 关闭靶场环境

四、防御

漏洞根源：Shiro 1.2.4 及更早版本中，AES 密钥硬编码在源码内，攻击者可自行构造 rememberMe 的恶意序列化内容，后端解密后触发反序列化，最终实现远程代码执行（RCE）。

4.1 核心

4.1.1 升级Apache Shiro版本

升级至 1.2.5 或更高版本。新版本移除了默认硬编码密钥，并且增加了反序列化相关安全校验，从根源修复该CVE漏洞。

4.1.2 自定义随机AES密钥

禁止使用源码自带默认密钥。如果暂时无法升级，必须更换shiro.ini中rememberMe的AES密钥。

  • 不要使用网上流传的默认密钥：kPH+bIxk5D2deZiIxcaaaA==
  • 使用密码学安全随机生成Base64密钥，并且妥善保管，不要泄露。

注意：仅修改密钥不能解决反序列化本身风险，只能临时缓解手段。

Apache Shiro 源码托管于 GitHub，1.2.4 版本源码可在 release 标签页下载：https://github.com/apache/shiro/releases/tag/shiro-root-1.2.4。

下载源码后查看core/src/main/java/org/apache/shiro/mgt/AbstractRememberMeManager.java，可找到硬编码的默认 AES 密钥，验证漏洞根源。

如果链接失效，访问我的仓库下载：https://gitee.com/jasminee0762/cyber-security/blob/master/%E6%BC%8F%E6%B4%9E%E5%A4%8D%E7%8E%B0/shiro-shiro-root-1.2.4.zip

4.2 反序列化安全加固

  1. 开启反序列化白名单
    高版本Shiro支持反序列化类白名单，只允许指定安全类被反序列化，禁止危险类。即使密钥泄露，也无法加载CC恶意利用链。
  2. 禁用不需要的rememberMe记住我功能。业务不需要“记住我”，直接关掉该功能，不存在rememberMe Cookie，漏洞入口直接消失。

4.3 Web应用层面加固

  1. Cookie安全属性：给rememberMe Cookie添加 HttpOnly; Secure
    • HttpOnly：JS无法读取Cookie，防止XSS窃取rememberMe值
    • Secure：仅HTTPS传输Cookie，防止中间人抓包劫持Cookie
  2. 最小权限原则：Tomcat/Web容器不要用root运行，使用低权限业务账号启动。就算RCE成功，也限制攻击者权限。

4.4 运维/检测防护

  1. WAF规则：添加特征检测，拦截rememberMe字段异常长、恶意加密载荷的Cookie请求；
  2. 日志审计：监控异常rememberMe Cookie、大量Java反序列化报错日志；
  3. 定期漏洞扫描，检测Shiro版本与默认密钥。

五、总结

本次复现 CVE-2016-4437 Apache Shiro 反序列化漏洞，漏洞成因是 Shiro 1.2.4 及之前版本存在公开的硬编码 AES 密钥。攻击者可自行构造带有系统命令的恶意序列化对象，利用公开密钥加密后放入 rememberMe Cookie 发送至目标。

服务端收到 Cookie 后，先 Base64 解码，再使用内置硬编码 AES 密钥解密，之后触发不安全的反序列化操作。在解析恶意对象时会激活 Gadget 利用链，自动运行我们预先写入的系统命令，从而实现远程代码执行 RCE。
