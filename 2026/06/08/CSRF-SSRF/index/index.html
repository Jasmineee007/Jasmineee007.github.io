CSRF与SSRF漏洞

发表于2026-06-08|更新于2026-06-09|Web安全CSRF
|总字数:2k|阅读时长:7分钟

一、CSRF（跨站请求伪造）

1. 简介与危害

  • 全称：Cross-site request forgery，跨站请求伪造，也叫one-click attack
  • 原理：攻击者伪造请求，欺骗已登录用户点击，利用浏览器自动携带Cookie的特性，以用户身份执行未授权操作
  • 危害：可实现转账、修改密码、修改个人信息、新增管理员等敏感操作

2. 工作原理

  1. 用户登录目标网站，浏览器存储认证Cookie（含sessionid）
  2. 服务器仅通过Cookie验证用户身份
  3. 攻击者诱导用户访问恶意页面/链接，浏览器自动携带Cookie发送请求
  4. 服务器误认为是用户本人操作，执行恶意请求

3. 攻击前提条件

  • 存在CSRF漏洞
  • 用户已登录目标网站
  • 攻击者了解请求协议包
  • 浏览器支持Cookie自动携带
  • 用户点击恶意链接/页面

4. Pikachu靶场实战

（1）CSRF(GET)攻击步骤

  1. 登录账号：kobe/123456

  1. 抓包获取修改信息的请求URL

GET /pikachu/vul/csrf/csrfget/csrf_get_edit.php?sex=3&phonenum=3&add=3&email=3%40pikachu.com&submit=submit HTTP/1.1

  1. 构造恶意HTML页面（script/img/form标签）
  1. 上传至恶意服务器，诱导用户访问
  2. 用户访问后，信息被悄无声息篡改

（2）CSRF(POST)攻击

  1. 利用Burp Suite生成CSRF PoC表单页面

构造恶意HTML页面，放到恶意服务器上

  1. 诱导已登录用户访问，自动提交POST请求完成攻击

5. 自动化工具

  • Burp Suite：拦截请求→Action→Generate CSRF PoC→生成HTML攻击页面
  • OWASP CSRFTester：代理端口默认8008，拦截请求→修改参数→生成HTML（GET选IMG，POST选Forms）

6. 防御方法

（1）用户层面

  1. 不点击恶意链接、不访问可疑网站
  2. 关键网站使用后及时退出登录
  3. 关键操作进行二次验证（短信、邮件、人脸识别）

（2）开发层面

同源策略：让关键操作只来自自身域名的请求，不接受跨域请求

  1. CSRF Token：服务端会话生成随机Token，请求携带并验证
  2. 验证来源：服务端检查Referer/Origin头，确保请求来自可信域
  3. 双重提交Cookie：客户端与服务器同时校验Token
  4. 请求方法限制：敏感操作服务端只接受 POST/PUT/DELETE，禁用GET
  5. SameSite Cookie：设置为Strict/Lax，限制跨站Cookie发送

补充：

1、 SameSite Cookie 是什么

SameSite 是 Cookie 的一个属性，用来告诉浏览器：跨站请求时，要不要把 Cookie 带过去。它有三个值：Strict、Lax、None，其中前两个是 CSRF 防御的核心。

2、SameSite=Strict

  • 规则：任何跨站请求，都不携带 Cookie
    • 不管是点击链接、提交表单，还是 <img>/<script> 跨站请求，只要不是在当前域名的页面里发起的，Cookie 都不会带过去。
  • 效果：CSRF 攻击完全没法用，因为浏览器根本不会把用户的认证 Cookie 传给目标网站。
  • 缺点：用户体验差。比如你从别的网站点链接跳过来，Cookie 不携带，会直接变成“未登录状态”。

3、SameSite=Lax（浏览器默认值）

  • 规则：只允许“安全的导航型GET请求”携带Cookie
    • ✅ 允许：用户主动点击跨站链接、地址栏输入地址这种导航式GET请求，会带Cookie。
    • ❌ 禁止：跨站的POST表单提交、<img>/<script>/<iframe> 自动发起的请求，不会带Cookie。
  • 效果：既防住了绝大多数 CSRF 攻击（因为CSRF常用POST或自动GET请求），又不影响用户正常跳转体验。
  • 适用场景：绝大多数网站的默认配置，平衡安全和体验。

二、SSRF（服务器请求伪造）

1. 简介与危害

  • 全称：Server-Side Request Forgery，服务器请求伪造
  • 原理：攻击者构造请求，由服务端发起请求，访问内网/本地资源
  • 核心特点：服务端可访问外网无法触及的内网系统

2. 业务场景

  • 远程图片加载、URL采集、在线翻译、文件读取等
  • 服务端未校验用户传入的URL，导致恶意请求被执行

3. 攻击利用方式

内网探测（HTTP）

  • http://127.0.0.1:80
  • http://127.0.0.1:3306（探测数据库端口）

本地文件读取（file协议）

  • file:///C:/Windows/System32/drivers/etc/hosts

内网服务探测（ftp协议）

  • ftp://192.168.0.19:21

4. 危害

  • 内网端口扫描
  • 内网Web应用指纹识别
  • 攻击内网应用
  • 读取服务器本地文件

6. 漏洞成因

服务端提供外部数据获取功能，但未对目标地址做过滤与限制

7. 防御方法

  1. 校验请求参数，禁止访问内网段IP
  2. 限制协议仅允许HTTP/HTTPS，禁用file、ftp等协议
  3. 统一错误信息，避免泄露内网端口状态
  4. 过滤返回内容，验证响应数据格式

三、CSRF与SSRF核心区别

维度 CSRF SSRF
攻击发起方 客户端（用户浏览器） 服务端
攻击目标 外网Web应用 内网/本地服务器
利用核心 Cookie自动携带 服务端请求转发
防护重点 Token、SameSite、来源校验 IP过滤、协议限制

四、总结

Q1：CSRF 是什么？

跨站请求伪造

Q2：SSRF 是什么？

服务端请求伪造

Q3：CSRF 和 XSS 的区别是什么？

CSRF 是跨站请求伪造，XSS 是跨站脚本攻击

XSS利用的核心是窃取 cookie，直接使用 cookie 登录受害者账号；CSRF 利用的核心是诱导欺骗，不会获取受害者的信息，而是诱导受害者自己去执行某些恶意操作。

Q4：CSRF 的危害？

盗号：诱导受害者修改自己的密码，修改自己的绑定手机号，发送敏感信息

改个人信息：诱导受害者修改自己的头像、个性签名、改自己的昵称

诱导受害者执行命令

Q5：如何挖 CSRF 漏洞？

CSRF 一般无需白盒测试（代码审计），只有黑盒测试。

Q6：同源策略是什么？

浏览器默认的安全配置，不同源的两个网站之间不能互相读写资源，如 cookie 无法读取，XHR（XMLhttprequest，Ajax，axios）无法发送

Q7：同源网站是什么？

两个网站，协议一样，端口一样，域名和 IP 一样，就称为两个网站为同源。

Q8：jsonp 跨域漏洞是什么？

jsonp 跨域漏洞的产生原因是因为没有注意敏感信息，直接用 jsonp 传输了敏感数据。

Q9：CORS跨域漏洞是什么？

CORS 跨域漏洞的产生原因是因为没有注意敏感信息，直接用 CORS 传输了敏感数据。
