区分内网IP和外网IP

  • 为什么要区分？
    • 内网IP：像你家里面房间的编号，只有在你家内部才有效
    • 外网IP：像你家的门牌号，外面的人可以通过这个找到你
  • 怎么区分？
    • 内网IP：属于私有IP地址范围（10.0.0.0–10.255.255.255、172.16.0.0–172.31.255.255、192.168.0.0–192.168.255.255）
    • 外网IP：属于公网IP地址，可通过ISP分配，全球唯一，可被外部访问

Q1: UFW是什么？

UFW = Uncomplicated Firewall，Linux的简易防火墙

  • [UFW ALLOW] ☞ 防火墙允许了这个连接
  • IN=eth0 ☞ 从网卡eth0进来的
  • OUT= ☞ 没有出去的数据
  • SRC=203.0.113.88 ☞ 来源IP是 203.0.113.88
  • DST=10.0.0.10 ☞ 目标IP是 10.0.0.10（服务器的内网IP）
  • PROTO=TCP ☞ TCP协议（一种网络协议）
  • SPT=52341 ☞ 来源端口是52341
  • DPT=22 ☞ 目标端口是22 ← SSH端口

意思是：

Q1：EventID 是什么？

EventID（事件ID），主要出现在 Windows事件查看器(Event Log)，是Windows系统日志里每条日志的唯一编号，用来标记发生了什么类型的事件。

位置：事件查看器 → Windows日志（系统、安全、应用程序），每一条日志都有「事件ID」字段。

核心概念

  1. 同一个EventID代表同一类事件
    比如登录、注销、创建进程、账号登录失败，都会对应固定EventID。

注意：EventID是事件类型编号，不是日志序号；不同机器同一种行为EventID相同。

  1. 配套还有：
  • LogName：日志分类（Security安全日志 / System系统日志 / Application应用程序）
  • TaskCategory：任务类别
  • Message：事件详细描述
  • EventRecordID：日志记录序列号（每条日志递增，和EventID不是一回事，容易搞混）

Q1：DNS外带是什么？

DNS外带全称DNS带外数据传输

  • DNS 本身是把域名翻译成 IP 地址的
  • DNS 外带就是通过域名查 IP

DNS外带 = 把数据藏在域名里，让目标服务器自己去查DNS，攻击者在DNS服务器那头收数据。不经过HTTP，WAF拦不住。

Q4：UNC是什么？

UNC = Universal Naming Convention，通用命名规范

Windows 系统用来定位局域网共享文件夹 / 网络主机的路径标准。

固定格式： \\主机名\文件夹名

  • 开头两个反斜杠 \ 是 UNC 路径标志性开头
  • 第一段：网络主机 / 域名
  • 第二段：该主机下的共享目录

只要路径以 \\ 开头 = UNC 网络共享路径，DNS 外带注入就是利用这个特性逼服务器发起域名查询。

六、shiro攻击！

1. 题目

2. 解题思路

2.1 Shiro是什么？

Apache Shiro 是一个Java权限管理框架，有个”记住我”（RememberMe）功能——勾选后，下次访问不用重新登录。

漏洞：Shiro老版本把”记住我”的加密密钥写死在代码里，所有人都知道这把钥匙。

2.2 攻击原理

默认密钥 = 90F1FE6C8C64E43D9D799888C5C69A68

rememberMe Cookie 加密结构

Base64( IV(16字节) || AES-CBC密文 )

  • Base64 解码 rememberMe 值
  • 前 16 字节 = AES-CBC 初始向量 IV
  • 剩余二进制 = 加密后的序列化对象
  • 必须：密钥 + IV 同时齐全，才能解密得到 Java 序列化载荷

攻击者用这把公开的钥匙，把自己的恶意代码加密，放进Cookie里发给服务器。服务器收到后自动解密+执行 → 被攻破。

Q1：加密原理是什么？

  1. 字节 Byte

计算机里的所有数据，都是 0 和 1， 一个字节就是 8 个 0/1

一个字节可以表示 00000000 到 11111111，换算成十进制就是 0 到 255。

  1. 字节和文本的区别

字节是给程序看的（编辑器会显示乱码），文本是给人看的。

  1. 为什么需要 Base64 编码？

HTTP 协议是纯文本协议。Cookie头里如果直接放二进制乱码，传输过程中可能被中间设备篡改或截断。

  1. IV 是什么？

IV = Initialization Vector 初始化向量， 是对称加密（AES、CBC 模式）必须用到的一段随机字节数组。

AES-CBC 分组加密：

  • 明文切成固定长度块（AES 128 位 = 16 字节一组）
  • 第一个明文块，先和 IV 异或，再加密
  • 后面每一块，用上一块的密文作为下一块的 “向量” 异或

没有 IV：第一条明文相同，加密后的密文永远一样，容易被破解、撞库

IV 的目的：相同密钥 + 相同明文，每次加密得到不同密文，混淆首块数据

  1. cookie 的构造

不是单纯的 Base64 编码，而是使用了 AES-CBC 模式，需要使用 IV（初始量）

AES-CBC 逐块加密过程：AES 一次只能处理 16 字节。如果数据是 3200 字节，就要切分成 200 个 16 字节的小块，一块一块加密。而 IV 只管第一块，后面的块用前一块的密文当”IV”。

但 CBC 模式有个特点：每一块加密前，先和上一块的密文做XOR（异或），这样块与块之间就有了关联。

Cookie 里的密文是 200 个加密块拼在一起的完整结果

2.3 找 cookie

过滤HTTP请求中带rememberMe的Cookie，发现有一堆。有些短（正常用户），有些特别长（攻击payload）。

用 tshark提取所有 HTTP 请求中的 rememberMe Cookie 值。

-r 参数：读取本地离线抓包文件

-Y：显示过滤器

-T fields：输出模式为自定义字段（不输出完整抓包详情）

-e frame.number：输出数据包编号

-e http.cookie：输出这条包完整的 Cookie 字符串，核心就是提取 rememberMe=xxx 的值

Q2：脚本中，为什么需要填充？

补位，让数据长度刚好对齐。

PKCS#7 填充规则： 适用所有分组密码，分组长度 1~255 字节，AES 分组固定 16 字节。差 N 个字节， 在数据末尾追加 N 个字节，每个字节的值 = N。刚好 16 也要补， 如果不补，解密时会误把原始末尾字节当成填充删掉。

AES 加密要求数据长度必须是 16 的倍数。但数据不可能每次都刚好，比如 100 字节的数据，100 ÷ 16 = 6 余 4，差 12 字节才够。

补充： PKCS#7

PKCS#7 全称：Public-Key Cryptography Standards #7，公钥密码标准第 7 号规范，由 RSA 实验室制定。

PKCS#7 填充（Padding）：AES 分组加密用的补位规则

Q4：ysoserial 是什么？

ysoserial 是Java 反序列化漏洞专用 Payload 生成开源工具，安全研究员 Frohoff 开发。 专门造恶意序列化数据的工具，是打 Shiro、WebLogic、Fastjson 等 Java 反序列化漏洞的核心工具。

  1. 核心作用：

根据指定的命令 + 目标存在的 Java 类库，自动生成一段恶意序列化二进制数据；

目标程序读取这段二进制并执行反序列化时，自动触发远程代码执行 RCE。

  1. 利用链 /gadget 链：

工具内置几十套攻击链，每套对应一个第三方 Java 依赖包：

  • CommonsCollections1~7（CC 系列，Shiro 最常用）
  • CommonsBeanutils（CB 系列）
  • Spring、Groovy、JBoss、Tomcat 等专用链
  1. Gadget 链原理

Java 项目自带的原生类中，存在一串可连续调用的方法，反序列化流程会自动走完这串方法，最终执行系统命令。

ysoserial 把这条链封装好，你只需要输入要执行的命令，工具自动拼接成完整恶意序列化对象。
